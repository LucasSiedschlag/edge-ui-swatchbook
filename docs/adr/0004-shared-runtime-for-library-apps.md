# Shared runtime for Library apps

One `runtime` package (`@swatchbook/runtime`) supplies React hooks and a provider with no UI and no Library dependency. The six Library apps must not re-implement the simulated clock, Plant State and Simulator consistency, preferences, shortcuts, Tour and routing, because separate paths for the same fact drift and break Parity. We considered copying the logic per app, keeping a context per app, and building a shared UI kit; the first two duplicate behavior, while a shared UI kit couples behavior to rendering that must stay native to each Library. The cost is one more package.

Runtime also owns the Library registry and switcher URLs. The required `libraryId` selects the registry entry returned by `useLibrary()`, including `supportsDensity`: true for Ant Design and false for the two planned Libraries until built. An optional density override exists for tests. Apps derive the site's base from their Vite `BASE_URL` with `siteBaseFrom`, and `libraryUrl` retains the Screen and any valid frozen tick when switching Library.

Hash routing works under the static site's Library sub-paths without server rewrites. Invalid hashes are replaced with `#/deck` without adding a history entry, and hash queries survive navigation. During an active Tour, core's `stepForRoute` derives its index from the route, including digit navigation and browser Back. Start navigates to step zero; next and previous only navigate. Leaving the six Tour Screens ends it. Shortcut registrations receive their order during render, so effect order cannot let a parent outrank a child. A handler returning false lets the next older handler try.

The hidden `?tick=N` parameter freezes a session for Parity checks, including zero, within core's supported tick range. Search takes precedence over a hash query such as `#/deck?tick=4`; an invalid search tick is ignored without falling back to the hash. Without a valid tick, the shared clock uses `performance.now()` through an injectable source, retains its highest tick and stops at `MAX_TICK`. Apps read the tick only through `useSimulation()`. `usePlantState()` exposes memoised state and dispatch without causing a Screen to re-render on clock ticks alone.

The three presets are `office` (light, comfortable), `control-room` (dark, compact) and `night` (dark, comfortable). Applying one always saves its theme and density, including in a Library without density support. Its density controls remain unavailable, and the Library does not render that density. The displayed preset is derived from the shared stored values. Only language, theme and density persist, together under core's single `PREFERENCES_KEY` on the shared origin; Plant State and Tour reset on reload.

Runtime never handles the `close` action or prevents Escape. Each Library's native Drawer, Modal and dialog owns Escape, checked by the Parity suite. The core binding stays in the shortcut help; runtime handler types exclude `close`.

Core suppresses every shortcut for visible open dialogs in the target, its dialog descendants or the composed path, including native `<dialog open>` and nested shadow DOM. Hidden, aria-hidden, display-none and inert dialogs do not block shortcuts. The optional `modalOpen` RuntimeProvider predicate supplies an app fallback without scanning the document. Apps should configure Vite with `resolve.dedupe: ['react', 'react-dom']` so runtime and the app share React.
